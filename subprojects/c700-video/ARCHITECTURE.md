# 架构与数据边界

## 三条独立链路

**实时流**：通过小米账号授权和设备元数据建立 MISS/CS2 会话，补丁处理云中继及 RDT 通道。go2rtc 向消费者提供 RTSP/WebRTC。`c700` 是稳定逻辑入口，`c700_lan` 与 `c700_remote_sim` 是模式来源；切模式后需按宿主服务管理方式重启。模式切换脚本不等于自动网络故障切换控制器。

**录像备份**：摄像头本身作为 SMB 客户端向 Pi NAS 上传录像，不是 go2rtc/ffmpeg 持续写出的录像。历史备份可能追赶上传，文件 mtime 代表上传或修改时间，不能用作拍摄时间。

**录像元数据与保留**：Pi 周期读取设备 SD 时间线，N100 计算太阳夜间边界与候选计划，Pi 受限 agent 在删除前重新核验本地文件和索引。规划与执行分开，使远端计划无法绕过执行端检查。

## 时间与元数据契约

| 数据 | 语义 | 用法 |
|---|---|---|
| MP4 文件名开始/结束时间 | Asia/Shanghai 民用时间 | 拍摄区间与太阳夜间比较 |
| RDT `start_ts` | Unix epoch 秒 | 统一时间轴；展示时转 Asia/Shanghai |
| 文件 mtime | 上传/修改时间 | 避免清理正在写入的文件 |
| 观察点经纬度 | Astral 日出日落计算参数 | 不对文件名做额外真太阳时修正 |
| `motion`、`saved` | 设备时间线保护信号 | 决定是否具备清理资格 |
| `event_type`、`event_name` | 命令 11 的事件细化 | 审计与统计，不放宽删除权限 |
| `last_success_ts` | 索引最近成功时间 | 判断新鲜度，不代表全区间覆盖 |

CS2 通道 0 为控制、1 为 RDT、2 为媒体。命令 6 的每条 SD 记录包含开始时间、时长及 motion/saved/deleting 字段；时长字段为 0 时按 60 秒解释。命令 11 是事件类型补充。SQLite `segments` 使用 `(did, start_ts)` 作为键，保留设备滚动索引之外的历史元数据。保留元数据不代表 NAS 上一定有对应视频文件。

## 删除权限与故障处理

- 规划器要求索引成功时间在 30 分钟内、目标夜间已结束至少两小时、文件未在最近两小时修改，并且至少间隔 30 分钟的两次文件与时间线快照一致。
- 规划器仅在 Asia/Shanghai 的 01:00–05:00 执行；这是规划器的调度条件，不能宣称执行端独立实现相同时间窗口。
- 边界文件与跨越太阳边界的文件保留；索引缺失、空洞超过五秒、motion 或 saved 信号均阻止候选文件删除。HA/MQTT 事件前后 180 秒提供额外保护。
- Pi agent 核验计划原因、有效期、文件及索引，执行前重新读取本地时间线，并记录回执。既有测试覆盖重复计划的回执复用和边界文件保护。
- 断网、索引陈旧和上传延迟会推迟清理。保守保留增加存储压力，容量告警及磁盘状态必须独立观测，不能通过将 unknown 视为静止来节省空间。

## 与 HomeMind 的集成边界

当前可复用输出是标准视频流、SQLite 时间线以及 HA/MQTT 状态。后续视觉事件接口应至少携带来源、设备标识、拍摄区间、观测时间、事件类型、置信度和证据引用，并处理重复与过期事件。这是设计约束，尚不是已发布 API。

视觉判断只能作为 Context 证据。新风控制与其他设备动作仍由 HomeMind 的策略约束、白名单和用户授权决定。设备运动标签不能直接解释为“垃圾站压缩作业”。

## 可验证性与局限

历史记录在 2026-09-17 描述了约 1,670 条 SD 记录、约 25 小时覆盖及 Pi 3B 单次命令 6 约 1.2 秒；这些是样本观测，不是 SLA。事件样本的 579 个命令 6 运动起点与 579 个命令 11 事件精确匹配，支持该样本中的 enrichment 关系，不能据此推导所有固件均适用。

上游 go2rtc 提供视频系统与大部分协议实现，本项目的增量工作是 C700 适配补丁、协议研究、索引持久化、保留护栏和运行工具。历史播放/下载仍需与实时播放和 SD 索引读取分别验收。
