# 技术说明与验证演示

## 项目概述

本子项目服务于 HomeMind 的家庭环境管理场景，在 go2rtc 基础上适配小米 C700 的 LAN 与云中继接入，提供 RTSP/WebRTC 视频入口。摄像头主动通过 SMB 将录像备份到 NAS；RDT 索引器读取 SD 时间线并持久化到 SQLite。N100 负责夜间保留规划，Pi 负责实际执行与本地复核。未知状态不删除，执行端重新验证时间线，以降低断网、索引过期和备份延迟导致的误删风险。视频与时间证据为后续视觉理解提供输入，完整视觉推荐闭环仍待集成。

本项目基于上游 go2rtc 的视频与协议能力，增量工作集中在 C700 适配、元数据索引和录像保留流程。

## 设计问题与工程取舍

| 问题 | 讲解重点 | 可展示证据 |
|---|---|---|
| 为什么不是只接一个 RTSP URL？ | 小米专有会话、网络路径与标准出口的适配 | `patches/`、模式脚本 |
| 如何确认协议字段？ | App 操作、抓包、插件静态分析与实机样本交叉核对 | 历史研究笔记、RDT 索引器说明 |
| 为什么不用文件修改时间判夜间？ | 拍摄时间和延迟上传时间不同 | 文件名时区测试与 backlog 记录 |
| 为什么拆 planner / agent？ | 远端编排与本地执行校验分别承担责任 | `controller.py`、`pi-agent.py` |
| 断网或 motion 实体 unavailable 怎么办？ | RDT 覆盖作为必要条件，MQTT 只增加保护 | 过期/缺段/运动保留逻辑 |
| AI 在哪里？ | 当前是感知基础设施，未来将视觉语义加入 HomeMind Context | 架构中的已实现与规划边界 |
| 是否评估过性能？ | 报历史样本、硬件和条件；没有统计就不报 P95/SLA | 索引器样本记录 |
| 哪些工程权衡？ | 私有协议维护成本、保守保留的容量代价、部署异构性 | 固定上游构建、运维与告警脚本 |

## 演示顺序

1. 打开 HomeMind README 的子项目入口，说明为什么环境智能需要视频证据。
2. 展示 LAN / cloud 的稳定流名设计；网络和账号已准备时播放 RTSP，并注明当前演示环境。
3. 展示脱敏的 SD 索引样本和 motion / saved / event 标签；把视频、元数据与语义区分开。
4. 运行离线保留测试，解释静止候选、运动保护、跨边界文件及重复执行回执。
5. 以“索引过期或时间线缺段”为例说明为什么保持文件，最后展示后续视觉事件接入方案。

演示无需执行真实录像删除。测试在临时目录生成文件；不要运行 setup、purge 或生产清理脚本作为演示。

源码环境已具备 `astral` 和 `paho-mqtt` 时，可运行：

```sh
cd tools/night-retention
python3 -m unittest -v test_retention
```

## 工程成果

- 基于 go2rtc 实现小米 C700 视频接入适配，提供 LAN/云中继模式与 RTSP/WebRTC 标准入口，作为 HomeMind 摄像头子系统。
- 研究 MISS/CS2 RDT 时间线协议，构建 SD 片段与设备事件元数据的 SQLite 持久化索引。
- 设计 N100 规划、Pi 本地复核的录像保留流程，结合太阳边界、索引新鲜度、运动保护与幂等回执降低误删风险。

性能和效果指标应由可复现的验收数据支持，当前不提供未经测量的空间节省比例、实时延迟或识别准确率。
